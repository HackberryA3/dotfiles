# dot 新方式の要件・受け入れ条件

本書は 2026-10-17 時点の合意を記録する。新方式の実装は未着手であり、ここに記載した対象を現在サポートしているという意味ではない。

## 目的と位置づけ

最小環境から開始できる、dotfiles・アプリ・開発環境の管理用コマンド `dot` を提供する。日常操作は日本語のインライン TUI、自動化・テストは非対話 CUI で行う。

既存スクリプトをそのまま再現するのではなく、設定ファイル、アプリ導入、開発ツール、シェル設定、OS 固有の設定など、利用目的を引き継ぐ。現行機能の具体的な移行一覧は設計時に作成し、代替・廃止が必要な項目は明示的に合意する。

mise・Ansible・chezmoi は採用候補であり、すべてを必須依存とすることは決めていない。実装言語、ライブラリ、保存形式も設計で決める。

## 対応環境

| 分類 | 対応目標 |
| --- | --- |
| Debian・Ubuntu 系 | Debian、Ubuntu、Kali、Linux Mint、LMDE |
| Arch 系 | Arch、Manjaro、EndeavourOS |
| Fedora・RHEL 系 | Fedora、AlmaLinux |
| openSUSE | Tumbleweed、Leap |
| Alpine | Alpine Linux |
| その他の OS | Windows、macOS |
| CPU | Linux: x86_64・ARM64、Windows: x64、macOS: Intel・Apple Silicon |
| シェル | Bash、Zsh、PowerShell。各 OS で利用可能な組み合わせを個別検証する |

- 通常リリースは提供元のサポート期間内にある安定版、ローリングリリースは検証時点の最新状態を対象とする。
- 開発版、サポート終了版、32 bit、Windows ARM64 は初期対象外。
- 実機のほか、VM、Docker などの最小コンテナ、サーバー環境も対象とする。
- GUI、systemd、sudo の存在を前提にしない。root・一般ユーザーを区別し、実行先の OS・CPU・実行環境を判定する。
- OS 名だけで全バージョン・全 CPU・全シェルの対応を保証しない。検証済みの組み合わせを記録し、未検証と区別する。

## 初回セットアップと権限

- 利用者による依存関係の手動導入を不要にする。Git を使う経路、または curl と短く覚えられる URL から開始できる経路を用意する。URL は未決定。
- 起動に必要な依存は自動準備する。自動導入は許容するが、依存が存在することを暗黙の前提としない。
- 起動準備後に TUI を開き、追加プロバイダ・アプリ・dotfiles は選択内容と変更予定を確認してから適用する。
- 管理者権限が必要な処理は事前表示する。昇格できなければ理由付きでスキップし、独立して実行できる処理は続行する。
- 未完了の対象を最後に表示し、要求された処理が完了しなければ非成功の終了コードを返す。

## アプリとプロバイダ

- プロバイダはアプリの導入・検出・更新・削除を担う仕組みとする。論理的なアプリ名と、プロバイダ固有のパッケージ名・配布元を分離する。
- セットアップで追加プロバイダを一覧から選択でき、後から追加・削除できる。
- OS 標準のプロバイダは自動認識し、暗く表示する。追加導入の選択対象にはせず、アプリの導入候補に含める。
- 標準プロバイダは、コマンドの存在だけでなく OS・リポジトリ・権限などから利用可否を判断し、未導入・権限不足などの状態を表示する。
- 別 OS 向けのコマンドが存在するだけでは、標準候補にしない。OS 標準プロバイダ本体は削除対象外。
- プロバイダの優先順位、アプリ単位の上書き、要求バージョン・更新方針を設定できる。具体的な既定順序は設定データとして決める。
- 条件を満たす利用可能なプロバイダへフォールバックできる。明示した導入元・バージョン条件を無断で変更しない。
- 管理中の導入元は、明示的な移行操作なしに変更しない。
- 定義済みのアプリを対象とし、利用者も定義を追加できる。プロバイダ全体のアプリ検索は初期対象外。
- 直接ダウンロード・インストーラーなども扱い、可能な範囲でバージョン・配置先・導入したファイル・削除方法を管理する。
- 既存アプリは自動検出するが、管理への取り込みは明示的に行う。管理外アプリを勝手に削除しない。
- 管理を解除して本体だけ残す機能は初期対象外。

## 選択プリセット

- プロファイルは、セットアップ時のアプリ選択を簡略化するプリセットとする。
- 複数プリセットをまとめて反映でき、重複は排除する。条件の衝突は検出し、無断で解決しない。
- 現在の選択への追加を基本とし、明示的な置き換えも選べる。
- 反映後はアプリ単位で自由に選択を変更できる。プリセット自体に適用後の ON/OFF 状態や継続的な依存関係を持たせない。
- 後日のプリセット定義の変更だけで、アプリを自動追加・削除しない。

## 削除・依存・移行

- アプリの OFF は、未導入なら導入対象から除外、管理下で導入済みならアンインストール予定を意味する。選択だけでは実行しない。
- アンインストールは本体のみを基本とし、設定・データを保持する。削除範囲を特定できる場合だけ追加削除を選べる。管理対象の dotfiles は別に扱う。
- 管理中アプリがある追加プロバイダを削除する場合、アプリ一覧を示して、移行・アプリも削除・キャンセルを選べる。管理中アプリを残したままプロバイダだけ削除しない。
- 移行にはプロバイダ共通の導入・検出・削除を使う。移行先の導入と動作・参照先の確認後に移行元を削除する。
- 移行先の導入に失敗した場合、dot は移行元の削除を実行しない。外部インストーラーの副作用を含む完全な復旧は保証しない。
- 併存条件・移行手順をアプリごとに網羅して記述する方式は採用しない。移行元の先行削除が必要なケースの自動移行は初期対象外。
- 依存解決はプロバイダに任せ、不足する依存だけ dot の定義で補う。完全な依存グラフを重複管理しない。
- dot が把握している依存を壊す削除は、そのまま進めず理由を表示する。管理外のアプリを含む完全な依存解析は行わない。
- 不要になった依存ツールは自動削除しない。依存の一括整理は初期対象外。

## 更新

- アプリ、追加プロバイダ、dot 本体を更新確認の対象とする。OS 全体のアップグレードと OS 標準プロバイダ本体の更新は対象外。
- 追跡可能な対象は、導入済み・利用可能・設定上許可されるバージョンを比較する。直接配布物も取得方法を定義できれば追跡する。
- 固定・メジャー固定・LTS・最新安定版など、提供元が扱える更新方針を指定できる。追跡不能・通信失敗・更新なしを区別する。
- 更新確認は変更を伴わない。TUI の一覧で対象を選び、適用で更新する。自動更新は初期対象外。
- 同じ設定・更新元を固定した再適用では、不要な再インストールや重複追記を行わない。通常の適用と更新を区別する。
- 初期設定例として Neovim は公式配布物の直接ダウンロード・最新安定版追跡を希望している。これは個別の設定であり、全アプリ共通の必須動作ではない。

## 実行環境の切替

- dot manager で管理ツールを一覧表示し、同じ役割の候補から一つを選ぶ。独立した ON/OFF で同時有効化する UI にはしない。
- 適用範囲は「現在のシェルのみ」「ユーザー既定として保存」。初期値は現在のシェルのみ。
- 一時選択は子プロセスに継承するが、他の既存ターミナルや独立して起動するシェルへ適用しない。永続選択は現在と次回以降のシェルへ適用し、他の起動済みシェルは変更しない。
- 優先順位は、シェルでの明示選択、プロジェクト設定、ユーザー既定、自動選択の順とする。一時選択を解除して既定へ戻せる。
- プロジェクトへの永続保存操作は初期対象外。既存プロジェクト設定との優先関係は扱う。
- 現在の選択・選択の由来・変更予定・実際のコマンド参照先を確認できる。切替で導入・削除を暗黙実行しない。
- Node.js を nvm に切り替えても、mise の他のツールは継続利用できる設計にする。関連コマンド群の整合性を保ち、プロンプト再表示・ディレクトリ移動後も選択を維持する。
- 切替先が利用できなければ元の環境を維持する。任意の組み合わせを保証せず、検証済みの OS・シェル・管理ツールの組み合わせを記録する。
- npm のグローバルアプリなどランタイムに依存するアプリは、ランタイムの切替だけで継続利用を保証しない。影響と実行元を確認できるようにする。
- 現在のシェルへ反映するためのシェル連携を設ける。起動済みの別プロセスは切り替えない。

## dotfiles と名前付き設定

- 普段編集するファイルは symlink または同等の方式で反映する。OS・端末差分が必要なものはテンプレートから生成し、適用する。
- 既存ファイルとの競合時は差分を表示し、保持してスキップ・バックアップして置換・中止を選べる。
- バックアップは過去のものを上書きせず、復元できるようにする。
- テンプレートのプレースホルダーを名前付き設定として管理し、TUI と非対話 CUI で確認・変更できる。
- 設定値の保存とファイル生成・適用は分離する。TUI では影響するファイルの差分を確認してから適用する。
- 共通の既定値は Git 管理、個人・端末固有の値は Git 管理外のローカル設定に保存し、ローカル値を優先する。
- 認証情報の保存・管理は対象外。API キーなどは利用者が用意した環境変数・既存の認証手段を利用する。

## UI と非対話操作

- dot 単体で、アプリ・プロバイダ・環境切替・設定・dotfiles・更新などのメニューを開く。dot manager などの直接入口も用意する。詳細なコマンド名は設計で決める。
- TUI は日本語のみ。全画面や代替画面を使用せず、通常画面の過去の出力を消さない。
- 一覧と選択ボタンを中心にし、複数選択はトグル、排他的選択は一つを選ぶ形式、値の入力はテキスト欄などを使う。
- キーボードだけで完結し、矢印と h/j/k/l に対応する。文字入力中は通常の入力を優先する。マウス対応は初期対象外。
- 選択中は変更せず、適用時にまとめて実行する。適用前はキャンセル可能。
- get・set・list などの非対話入口を用意し、TUI と処理を共有する。対象と操作が明示されていれば確認待ちせず実行し、情報不足ならエラーで終了する。
- 非対話環境で TUI を起動して入力待ちにしない。

## 失敗・中断・履歴

- 一部失敗時は依存する処理をスキップし、独立した処理は続行する。成功・失敗・スキップを最後に一覧表示し、失敗を成功扱いにしない。
- Ctrl+C では新しい処理を開始せず、可能な範囲で終了・後片付けし、完了済み・失敗・未実行を表示する。端末を正常な状態へ戻す。
- 完了した変更は自動で巻き戻さない。アプリを含む一括ロールバックは初期対象外。dotfiles はバックアップから復元する。
- 導入・更新・削除・移行・設定適用について、日時・対象・変更前後・結果をローカルに記録し、TUI と CUI で確認できる。
- 環境変数全体や認証情報は履歴に記録しない。
- 認証・再起動・再ログイン・GUI 設定などが必要な場合は、未完了の手動作業として表示する。

## 受け入れ条件

上記各節の動作を検証する。正式対応の表示には、対象環境で少なくとも次の実環境検証を必要とする。

| ID | 確認内容 |
| --- | --- |
| A1 | 最小構成から、文書の手順だけで起動できる。依存の手動準備を要求しない |
| A2 | 選択したアプリの導入・更新・削除と dotfiles の適用ができる。未選択対象を変更しない |
| A3 | 更新元と設定を固定した再適用で、不要な変更・重複追記が起きない |
| A4 | 対応シェルで管理ツールを切り替えられ、他の管理対象ツールを継続利用できる |
| A5 | 一時・永続・プロジェクト設定の優先順位と、シェル間の適用範囲が仕様どおりである |
| A6 | 管理外アプリを明示的に取り込める。取り込み前に削除しない |
| A7 | プリセットを複数合成・個別編集でき、反映後に継続的な依存関係を持たない |
| A8 | 利用可能なプロバイダ間で、移行先を確認してから移行元を削除できる |
| A9 | 既存ファイルの競合を確認でき、退避・復元で既存内容と過去のバックアップを失わない |
| A10 | 設定値の保存だけでは生成先を変更せず、適用前に差分を確認できる |
| A11 | 権限不足・通信失敗・導入失敗・中断を識別し、結果と終了コードが一致する |
| A12 | TUI をキーボードだけで操作でき、過去の出力を保持する。CUI は非対話で完結する |
| A13 | 更新確認は変更せず、選択した対象だけ更新する。追跡不能と更新なしを区別する |
| A14 | 履歴から変更前後と結果を確認でき、認証情報を記録しない |

モックテスト・構文検査・静的解析と、実パッケージを扱う VM・コンテナ・実機での検証を区別する。実際に確認した OS バージョン・CPU・シェル・プロバイダの組み合わせと日付を記録する。普段使いの端末で一括導入テストを行わない。

## 保留事項と設計への引き継ぎ

- dot env で表示する環境変数の範囲・見せ方は、試作で必要性を確認して決める。
- UI の配置、キー割当の詳細、コマンド体系、構成データの形式は設計で決める。
- 更新失敗・中断時に再実行可能な状態をどう保持するか、各プロバイダの対応操作と制約を設計・試作で確認する。
- ホストを変更しない UI・計画生成の試作から始め、代表環境でプロバイダとシェル連携を検証してから対応範囲を広げる。
- nightly・PR・worktree の運用は CONTRIBUTING.md に従う。
